# 振り返り

## 手順

1. `python3 scripts/analyze.py` を実行する。記述式（`log/history.jsonl`）と択一（`log/drill.jsonl`）を合わせて、分野ごとに次を出す
   - 判定：**苦手**（見込みが合格ライン未満）/ **ボーダー** / **得意**（合格ライン+15pt以上）/ **測定中**（記録が少ない）/ 未出題
   - 記述・択一それぞれの見込みと95%の幅、伸び（↑↓→）。「（確か）」は幅が合格ラインをまたがないもの
   - 苦手・ボーダーの分野の原因（択一と記述の差、最も多いミスの種類、その分野の弱点）
   - 繰り返している弱点（同じ用語・観点）
   - 細かい数字が要るときは `--json` を付ける
2. 記述式と択一の記録がどちらも3件未満なら「まだ傾向を出すには少ない」と伝え、`/question` か `/drill` を勧めて終わる
3. 必要なら `log/history.jsonl` の `weak` を読み、繰り返し出てくる弱点の中身（どの観点が抜けたか）を補う
4. 次の形で短く返す：
   - **苦手**：最大3つ。見込みと合格ラインとの差、原因を1行ずつ。「確か」でないものは「まだ断定できない」と添える
     - 「択一は取れるのに記述で落とす」→ 知識より読み方・書き方。解答例と要素の数を比べる練習
     - 「択一も記述も低い」→ `/drill <タグ>` で知識から固める
     - 「記述は取れるが択一で落とす」→ 細かい用語・数値の穴。参考書で確認
   - **得意**：最大3つ。伸びが ↓ なら「落ちてきている」と一言
   - **ミスの傾向**：knowledge / reading / writing のどれが多いか。それぞれの対策を1行ずつ
     - knowledge が多い → 該当用語を参考書で確認し、関連する選択式の過去問を解く
     - reading が多い → 解く前に設問を先に読み、本文に線を引くつもりで根拠を探す練習
     - writing が多い → 解答例と自分の解答の「要素の数」を比べる。字数の8割以上を埋める
   - **繰り返す弱点**：用語や観点を最大5つ
   - **解答中の質問**（analyze.py の「解答中の質問」。あれば）：質問が多い分野と、何度も意味を聞いた言葉。言葉の質問が多い分野は `/drill <タグ>` と単語帳を勧め、「何を聞かれているか」が多ければ reading の対策を勧める。質問は見込み（点数）には入っていないと添える
   - **測定中・未出題**：重みの大きい分野が残っていれば、先に測ることを勧める
   - **次の3問**：`python3 scripts/route.py --json` が次のセットで選ぶ論点から3つ（出題の順番は route.py に合わせ、別の順番を勧めない）。バンクの在庫が足りなければ `/prepare` を勧める
5. 学習者が望めば、この内容を `log/review-<YYYYMMDD>.md` に保存する
