# 「正解 ＝ 理解」ではない問題への対応計画

択一は、○でも理解しているとは限らない。勘で当たった、他の選択肢が分かりやすく誤りだった、似た言葉の片方を覚えていただけ、といった場合である。
次の3段階で、○の質を測れるようにする。1 は実装済み。2・3 はこれからで、1 の記録がたまってから、どの論点で必要かを見て決める。

## 1. 確信度を記録する（実装済み）

- 択一を答えるとき、画面で「根拠がわかる（`sure`）／消去法（`narrowed`）／勘（`guess`）」を選ぶ。選ぶまで「答える」は押せない
- `log/bank.jsonl` の1行に、任意の `confidence` として書く。別ファイルにはしない。ない行（この機能より前の記録、`/drill` の記録）は「不明」として扱い、あとから書き足さない
- 論点ごとの見込み（`learn/route.py` の `CONF_WEIGHT_*`）で、1問が動かす強さを変える

  | 結果 | 根拠がわかる | 消去法 | 勘 | 不明 |
  |---|---|---|---|---|
  | ○ | 1.0 | 0.6 | 0.3 | 1.0 |
  | × | 1.3 | 1.0 | 0.7 | 1.0 |

- 答え合わせで、勘・消去法の○と、根拠ありの×にひとこと表示する
- 未対応：分野ごとの分析（`scripts/analyze.py`）は確信度を使っていない

## 2. 選択肢の理由を確かめる（計画）

- 目的：○でも「なぜほかが違うか」を言えるかを見る
- 対象：確信度が `narrowed`・`guess` の○、または `sure` の○のうち紛らわしい組の問題
- 形：答え合わせのあとに、「ほかの選択肢のうち1つを選び、なぜ違うかを一言で書く」。正誤は `bank/keys/` の選択肢ごとの解説と照合し、`/grade-set` が判定する
- 記録：`log/bank.jsonl` に任意の項目を足す案（`why`：書いた理由、`why_ok`：照合の結果）。足す前に `schema/` と `docs/formats.md` を直す
- 決めること：全問に出すと重いので、出す条件（確信度、難しさ、論点）と、1セットあたりの上限

## 3. 単語・対比テスト（計画）

- 目的：取り違えやすい言葉を、答えと切り離して問う
- 素材：`log/glossary.jsonl` の言葉と、`bank/keys/` の選択肢ごとの解説。新しい問題は作らない
- 形：
  - 単語：用語を出して、意味を選ぶ（または一言で書く）
  - 対比：取り違えやすい組（例：ID トークンとアクセストークン、反射型と格納型）を出して、違いを答える
- 対象の選び方：誤答した問題の言葉、確信度が `sure` の×、単語帳で何度も聞かれた言葉を優先する
- 記録：既存の `log/bank.jsonl` に載せるか、別の種類（`kind`）にするかを、実装前に決める。見込みへの重みは別に決める
