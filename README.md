# 記述式問題トレーナー（Claude Code 用）

Claude Code で記述式問題の「出題 → 解答 → 採点 → 弱点更新」を回す、学習用の雛形リポジトリです。
勉強の題材は決まっていません。最初に `/setup-exam` で対象の試験を設定すると、その試験に合わせて問題を作り、採点します。リポジトリには試験の中身（分野・問題・記録）を一切入れていません。

必要なのは [Claude Code](https://docs.claude.com/en/docs/claude-code/overview) と Python 3（成績集計用、標準ライブラリのみ）だけです。サーバーやアカウント登録は要りません。ターミナルの代わりに[ブラウザから使う](#ブラウザから使うセルフホスト)こともできます。

## しくみ

```
/prepare ──▶ 採点基準を先に作って保存 ──▶ verifier が解けるか検証 ──▶ bank/ に貯める
                                                                        │
/question ──▶ route.py がバンクから選ぶ ──▶ 問題を表示 ◀───────────────┘
                                              │
/grade  ◀──── 解答（ファイル or チャットに貼る） ◀┘
   │
   ├─ grader が採点基準どおりに採点
   ├─ results/ に講評、log/history.jsonl に成績を記録
   └─ 弱点から次の分野を提案 ──▶「続けて」で /question に戻る
```

- **採点基準は問題を作るときに先に保存**するので、解答を見てから甘くなることがありません
- **出題者・検証者・採点者を分けています**（`.claude/agents/`）。verifier は採点基準を見ずに解いて、問題の曖昧さを潰します
- **ミスを3種類に分けて記録**します：`knowledge`（知らなかった）/ `reading`（本文を読み落とした）/ `writing`（書き方で落とした）
- **問題はその場で作らず、問題バンクから出します**。`/prepare` で好きなときに作り、verifier の確認を通した問題だけを、`scripts/route.py` が記録から選びます（在庫が足りなければ、ある分だけ出して知らせます）
- **択一ドリル**（`/drill`）で、選択式の知識問題もまとめて回せます。問題はバンクの択一です
- **穴埋め**で、数字や語句1つで答える問題（計算、用語、簿記の仕訳など）も練習できます。問題文の表などに置いた空欄［ア］［イ］…に答えると、その場で採点します（`exam/profile.md` に「穴埋め問題」の節を残すと `/prepare` が作ります）
- **図や写真も扱えます**。問題の図は文字（表・Mermaid）か画像で、解答は手書きの写真やスクリーンショットでも採点できます

## セットアップ

クローンした直後は、試験の設定も問題も入っていない空の状態です。次の順に進めます。

1. **用意する**：[Claude Code](https://docs.claude.com/en/docs/claude-code/overview) と Python 3（標準ライブラリだけで動くので `pip install` は不要）
2. **取ってくる**：このリポジトリをクローンして、そのフォルダで Claude Code を起動する

   ```bash
   git clone https://github.com/imohiyoko/learn.git && cd learn
   claude
   ```

   学習記録も別の端末と同期したいなら、GitHub の「Use this template」で **private** リポジトリとして作ってからクローンします（[何が push されるか](#何が-push-されるか)）
3. **試験を設定する**：`/setup-exam <資格の名前>` を実行して質問に答える
   - 試験の形式（本文の長さ・設問数・字数制限・目安時間）、択一で練習するか、出題分野、採点で厳しく見たい点、自分の経験を聞かれます。分からない項目は Claude が公式情報を調べて提案します
   - 答えると `exam/profile.md` ができます。あとから直すときも `/setup-exam` か、このファイルを直接編集します
   - 公式の過去問・解答例・シラバスがあれば、先に `refs/` に置いておくと、分野や形式の提案がそれに沿います
4. **問題を用意する**：`/prepare` で問題バンクを作る（論点の一覧と、択一・穴埋め・短い記述・長文）。1回で作る数に上限があるので、足りなければもう一度実行します
5. **解く**：`/question` で記述式を1問、`/drill` で択一をまとめて。解き終わったら `/grade` で採点します

ブラウザで使うなら、手順2のあとに `python3 webui/server.py` を起動して http://127.0.0.1:4870/ を開き、ホームの「資格を選ぶ」に資格の名前を入れても同じ設定ができます（[ブラウザから使う](#ブラウザから使うセルフホスト)）。

設定がすんだかどうかは `python3 scripts/stats.py` で確かめられます（分野タグの一覧が出れば準備完了）。

## 何が push されるか

このリポジトリは**雛形だけを共有**する前提です。次のものは `.gitignore` で追跡対象外なので、使い込んでも push されません。

- `exam/`：自分の試験プロファイル（学習者メモを含む）
- `examples/`：前に作った試験プロファイルの控え（試験を切り替えるときに使う）
- `questions/` `rubrics/` `answers/` `results/` `log/`：学習の記録
- `refs/` と `past-*`：公式過去問など著作物の転記

フォルダ構造を保つための `.gitkeep` と、`refs/README.md`（置く資料の説明）だけが追跡されています。別の端末でも学習を続けたい場合は、このリポジトリをテンプレートとして **private** リポジトリを作り、`.gitignore` の該当行を外して使ってください。`refs/` と `past-*` は公式資料の転記を含むので、private でも外さないことをおすすめします。

## ブラウザから使う（セルフホスト）

ターミナルで操作する代わりに、ブラウザで学習の種類・分野・問題数を選んで回せます。自分の PC で動かすだけで、アカウント登録やデータベースは要りません。
画面はページごとに URL が分かれていて（`/bank/<問題id>`・`/sets/<セットid>` など）、戻る・ブックマーク・再読み込みが効きます。

- **ホーム**：いまの資格と成績のまとめ、おすすめの1問、書きかけの問題の続き。分野ごとのカード（苦手な順）から「記述を1問」「択一」をすぐ始められます。「資格を選ぶ」で資格の名前を入れて Claude と対話で設定するか、前に作った設定（`examples/`）に切り替えます
- **学習する**：記述式 / 択一ドリル / 取り込んだ過去問 / 過去問の取り込み / 振り返り を選び、分野（おまかせ＝弱点から自動）と問題数を指定して「はじめる」。問題は画面に表示され、記述式は解答欄に書いて「保存して採点する」、択一は返信欄に `1ア 2ウ …` で答えます
  - 記述式の解答欄は設問ごとに分かれ、`28 / 40字` のように字数を数えます（改行は数えない）。9割を超えると色が変わり、超えると赤くなります
  - 右下のタイマーは書き始めると動き出し、目安時間（`time_limit_min`）を過ぎると知らせます。一時停止した時間を除いた分が `elapsed_min` として解答に残り、成績の所要時間に使われます
  - 「わからないとき・不安なとき」から、言葉の意味・設問の聞き方などを Claude に聞けます。答えの方向は教えず、言葉の意味と読み直す場所だけを返します
  - 問題バンクのセット（択一ドリルも）では、問題の下の「わからない言葉を聞く」に言葉を1つ入れると、一般的な意味が返ります（単語帳に意味があればすぐ、なければ Claude が書きます）。答える前の択一で選択肢に出てくる言葉は、答えたあとに意味を出します
  - 質問は `log/asks.jsonl` に残ります。点数や苦手の判定には入れず、「成績」と振り返りで質問の多い分野・何度も聞いた言葉として出し、採点ではミスの種類（知識・読解）の判断に使います
- **問題**（`/bank`）：`/prepare` で作った問題バンクの一覧。形式・分野・論点・難しさ・状態（確認待ちなど）で絞り込み、正答率の低い順にも並べられます。1問のページ（`/bank/<id>`）では本文・成績を見て、正解は「正解を見る」を押したときだけ出します。分野タグ・論点（先頭が主）・難しさ・本文・正解キーを編集でき、本文か正解キーを変えると「確認待ち」に戻って次の `/prepare` で verifier が確かめるまで出題されません。削除はゴミ箱（`bank/trash/`）に移すだけで、一覧から戻せます。解いている途中のセットの問題は変えられません
- **論点**（`/concepts`）：論点ごとの見込み（苦手・ボーダー・得意）と、まだ解いていない問題の在庫・足りない数。論点を押すとその論点の問題の一覧へ
- **単語帳**：解答中に意味を聞いた言葉と、採点で知識不足だった用語が自動で入ります（意味は Claude が書きます）。何度も聞いた言葉ほど上に出て、カードで覚えられます。「覚えていない」言葉は択一ドリルにも混ぜて出ます
- **資料**：過去問の問題冊子・解答例・採点講評やシラバス（PDF・画像・テキスト、50MB まで）をアップロードして `refs/` に保存し、そのまま「取り込む」で問題にできます
- **成績**：`scripts/analyze.py` と同じ得意・不得意の判定を表で表示（Claude を呼ばないので無料・一瞬）
- **履歴**：出題済みの問題・解答・講評を見返す（採点基準 `rubrics/` は画面から読めません）
- **設定**：Claude と対話して試験を設定、または前に作った設定（`examples/`）をコピー。`exam/profile.md` を画面で編集

画面は依頼を Claude Code に渡して返事を見せるだけで、出題・検証・採点はこのリポジトリのスキルがそのまま行います。記録されるファイル（`questions/` `log/` など）もターミナルで使うときと同じなので、両方を行き来できます。Claude Code への渡し方は2通りあります。

### A. PC の Claude Code に `/loop` で処理させる（既定）

```bash
python3 webui/server.py          # → http://127.0.0.1:4870/（使用中なら 4871, 4872, ... と順に試す）
claude                           # 別のターミナルで、このフォルダで起動して
> /loop 1m /inbox                # 1分ごとにブラウザからの依頼を処理する
```

- 画面での操作は `inbox/<依頼>/NNN-user.md` に置かれ、`/inbox` スキル（`.claude/skills/inbox/`）が処理して `NNN-claude.md` に返事を書きます。サーバー自身は Claude を呼びません
- いつもの Claude Code（サブスクリプションでも API キーでも）をそのまま使います。1つのセッションが回り続けるので、会話の流れも引き継がれます
- 放っておいても進むように、`claude --permission-mode acceptEdits` で起動するか、`python3 scripts/stats.py` `python3 scripts/analyze.py` `date` `mkdir` などを許可しておくと止まりません
- 依頼は並べて置けます。返事が来るまで、画面には「Claude Code が拾うのを待っています」と出ます

### B. サーバーが `claude -p` で処理する（API キーでも可）

常駐の Claude Code を用意しないときは、サーバーが依頼ごとに `claude -p "/question <タグ>"` を起動します。

```bash
python3 webui/server.py --runner cli
ANTHROPIC_API_KEY=sk-ant-... python3 webui/server.py --runner cli   # API キー（従量課金）で動かす
```

- 認証は `claude` コマンドと同じです：ログイン済みのサブスクリプション、`CLAUDE_CODE_OAUTH_TOKEN`（`claude setup-token` で発行）、`ANTHROPIC_API_KEY` のどれでも動きます
- `claude -p` は対話で許可を求められないので、スキルが使う操作（このフォルダ内のファイル編集と `scripts/` の実行など）だけを許可して動かします（`learn/web/jobs.py` の `ALLOWED_TOOLS`）。サブエージェント（verifier・grader）の出力や、採点基準を書き込む操作の中身は画面に流しません
- 同時に動かせる作業は1つだけです。問題の作成には数分かかります
- 使うモデルを変えたいときは `LEARN_CLAUDE_ARGS="--model sonnet"`

### スマホなど別の端末から使う

既定では自分の PC（127.0.0.1）からしか開けません。同じ LAN の端末から使うときはトークンを決めて起動し、`?token=` 付きの URL を一度開きます（以後は Cookie で覚えます）。

```bash
LEARN_TOKEN=$(python3 -c "import secrets; print(secrets.token_urlsafe(24))") python3 webui/server.py --host 0.0.0.0
# → http://<PCのIPアドレス>:4870/?token=<そのトークン>
```

4870 が使用中で別の番号で起動したときは、起動時に表示された番号に読み替えてください。

トークンは英数字と `-` `_` だけにしてください（`#` や `&` を含むと URL で途中までしか送られず、開けません）。

インターネットに直接公開する使い方は想定していません。外から使いたいときは Tailscale などの VPN 越しにしてください。

## 問題バンクとセット（苦手の洗い出しと穴埋め）

問題はその場では作りません。前もって用意しておき、次に何を解くかは `scripts/route.py` が記録から機械的に決めます。記述式（`/question`）も択一ドリル（`/drill`）も、出すのはバンクの問題だけです。同じ記録からは同じセットになるので、「なぜこの問題が出たか」をいつでも説明できます。

1. **準備（`/prepare`）**：分野タグを「論点」に分けた一覧（`exam/concepts.md`）を作り、論点ごとに択一3問（易・中・難）と短い記述1問、分野ごとに本番形式の長文1問を、採点基準つき・verifier の確認つきで `bank/` に貯めます。作るのは学習者が好きなときに（ホームの「問題バンクを作る」か `/prepare`）。1回で作る数には上限があるので、足りなければもう一度実行します。単語帳でまだ覚えていない言葉も、ここで択一にします
2. **セット（ホームの「今日のセット」）**：route.py が10問前後を選びます
   - まだ測れていない論点が多いうちは**洗い出し**（測れていない論点を、分野の重みの大きい順に）
   - 測れてきたら**穴埋め**（苦手な論点に、正答率が65%前後になる難しさの問題を）。間違えた問題は 1・3・7日あけて**やり直し**、得意な論点もときどき**確認**します
   - 1つのセットで同じ論点は1問まで、1つの分野からは半分まで
3. **解く**：1問ずつ表示します。択一は選択肢をクリックして「答える」と、その場で正誤と解説が出ます。短い記述は字数を数えながら書いて保存します
4. **提出**：`/grade-set` が記述を採点し、問題ごとの解説、論点ごとの見込みの変化（前→後）、過去の記録と合わせた間違い方の傾向、次に埋める穴をレポート（`reports/<セット>.md`）に保存します。「履歴」の「セットとレポート」から見返せ、「間違えた問題だけ」に絞れます
5. **長文**：ホームの「本番形式の長文を1問」は、バンクの長文から route.py が選んだものを `/question` で出します（なければ「バンクに長文がない」と知らせます）

論点ごとの見込みは「成績」の「論点ごとの見込み」で見られます（`python3 scripts/route.py --model` と同じ）。バンクの択一・記述の結果は、分野ごとの判定（`scripts/analyze.py`）にも入ります。

「択一ドリル」は、バンクの択一だけで同じようにセットを作ります（分野と問題数を選べます）。

## コマンド

| コマンド | やること |
|---|---|
| `/question [タグ]` | バンクの長文を1問出題。どれを出すかは route.py が決める |
| `/drill [タグ] [問題数]` | バンクの択一をまとめて出題し、その場で答え合わせ（`1ア 2ウ …` で回答） |
| `/grade [id]` | 採点・講評・記録・次の提案 |
| `/review` | 得意・不得意な分野とその原因、ミスの傾向、次の3問 |
| `/setup-exam` | 試験の設定・切り替え |
| `/import-past <年度> <問>` | `refs/` の公式過去問を取り込み、公式解答例で採点できるようにする |
| `/prepare [タグ] [数]` | 問題バンクを作る・作り足す（論点の一覧、論点ごとの択一3・短い記述1（profile で使うなら穴埋め2）、分野ごとの長文1） |
| `/grade-set <セット>` | 提出されたセットの記述を採点し、解説と知識の分析のレポートを書く |
| `/glossary [言葉、…]` | 単語帳（`log/glossary.jsonl`）に、意味の入っていない言葉の意味を書き足す |
| `/inbox` | ブラウザの画面から届いた依頼を処理する（`/loop 1m /inbox` で常駐） |

解答は `answers/<id>.md` に書いても、チャットに直接貼っても大丈夫です。スマホから使うときはチャットに貼る方が楽です。
紙に手書きした解答は、写真をチャットに貼るか `answers/<id>-1.jpg` のように置けば、文字に書き起こしてから採点します（読めない字だけ確認されます）。

## 図のある問題

- 生成問題の図（構成図・シーケンス・画面）は、まず表・コードブロック・Mermaid で表現します。絵でないと伝わらない図だけ SVG にして `questions/assets/` に置きます
- 公式過去問を `/import-past` で取り込むとき、`pdftoppm`（poppler）が入っていれば図のページを画像にして `questions/assets/` に置きます。なければページ番号で参照します
  - macOS：`brew install poppler`、Ubuntu：`sudo apt install poppler-utils`

## 出題分野の選び方

出題もおすすめの分野も、`scripts/route.py` が論点ごとの見込みから決めます（上の「問題バンクとセット」の選び方）。分野の重みは `exam/profile.md` の分野タグ表、論点の重みは `exam/concepts.md` で調整できます。

`scripts/stats.py --next` は、これまでの記録だけで分野を並べる簡単な推薦です（参考用）。

## 得意・不得意の分析

`/review`（または `python3 scripts/analyze.py`）で、記述式と択一の記録を合わせて分野ごとに判定します。

| 判定 | 意味 |
|---|---|
| 苦手 | 見込みが合格ライン（`exam/profile.md` の合格基準。読めなければ60%）未満 |
| ボーダー | 合格ライン〜+15pt |
| 得意 | 合格ライン+15pt以上 |
| 測定中 | 記録が少ない（記述式は3件、択一は5問に満たない。副タグとして出た記録は0.5件と数える） |

- 見込みは分野ごとに、記述式と択一を**別々に**見積もります。1回ごとに少しずつ動かす方式（Elo）なので、新しい結果ほど強く効き、記録が少ないうちは50%に寄せます
- 判定には、記録が足りている形式のうち**低い方**を使います。択一で満点でも記述式で落としていれば「苦手」になります
- 見込みには95%の幅を付け、幅が合格ラインをまたがなければ「（確か）」と表示します
- 苦手・ボーダーの分野には原因の見当を付けます：択一と記述の差（知識の問題か、読み方・書き方の問題か）、最も多いミスの種類、その分野で記録された弱点
- 分野をまたいで繰り返している弱点（同じ用語・観点）も拾います

考え方は、SaaS 版の [imohiyoko/learning](https://github.com/imohiyoko/learning) の学習者モデル（ADR 0018）を、1人・ファイルだけで回せる形に縮めたものです。概念辞書・難易度・記憶（FSRS）は扱わず、分野タグの単位で見ます。

## 公式過去問との併用（おすすめ）

生成問題より、公式の過去問と解答例で採点する方が精度は上です。

1. 試験の実施団体のサイトなどから問題冊子・解答例・採点講評をダウンロードして `refs/` に置く（ブラウザの「資料」からアップロードしてもよい）
2. `/import-past r06a q1` のように取り込む
3. `/question past-r06a-q1` で解く

過去問を一巡したら、生成問題で量を稼ぐ使い方がおすすめです。
`refs/` と `past-*` のファイルは公式資料の転記を含むため、`.gitignore` でコミット対象外にしています。

## カスタマイズ

| 変えたいこと | 触るファイル |
|---|---|
| 試験・形式・分野 | `exam/profile.md`（または `/setup-exam`） |
| 採点の厳しさ | `exam/profile.md` の採点方針、`.claude/agents/grader.md` |
| 問題の作り方 | `.claude/skills/prepare/SKILL.md` |
| 択一の選択肢の数・問題数 | `exam/profile.md` の「択一問題」 |
| 結果の書式 | `templates/` |
| 出題の選び方 | `scripts/route.py`（先頭の定数） |
| 得意・不得意の判定 | `scripts/analyze.py`（先頭の定数） |

`/setup-exam` で作ったプロファイルは `examples/<略称>/profile.md` にも控えが残ります（git 管理外）。別の試験に切り替えてから戻るときに使えます。

## ディレクトリ

```
.
├ CLAUDE.md               # Claude への全体ルール
├ .claude/
│  ├ skills/              # question / drill / prepare / grade / grade-set / review / setup-exam / import-past / glossary / inbox
│  └ agents/              # verifier（検証役）/ grader（採点役）
├ exam/profile.md         # 今の試験の設定（git管理外、/setup-exam で作成）
├ examples/               # 前に作った試験プロファイルの控え（git管理外）
├ templates/              # プロファイル・問題・採点基準・解答・結果・ログのひな形
├ scripts/stats.py        # 成績集計と出題分野の推薦（Python標準ライブラリのみ）
├ scripts/analyze.py      # 得意・不得意の分析（記述式と択一を合わせて）
├ scripts/route.py        # 問題バンクから次に解く問題を選ぶ
├ learn/                  # scripts/ と webui/ が共有する中身（ファイルの読み込み・学習者モデル・集計・分析・出題の選択。web/ はサーバーの中身）
├ bank/ sets/ reports/     # 問題バンク（items と正解の keys）・セット・レポート（git に入らない）
├ webui/                  # ブラウザから使うためのローカルサーバーと画面（python3 webui/server.py）
├ inbox/                  # 画面から Claude Code への依頼（/inbox で処理。git管理外）
├ tests/                  # スクリプトのテスト（python3 -m unittest discover -s tests）
├ questions/ rubrics/ answers/ results/
├ questions/assets/       # 問題の図（画像・SVG）
├ log/history.jsonl       # 記述式の成績
├ log/bank.jsonl          # 問題バンクの成績（1問1行。択一ドリルもここ）
├ log/drill.jsonl         # 以前の択一ドリルの成績（いまは書かない。分析には入る）
└ refs/                   # 公式資料（git管理外）
```
